Por que CoreRealtime?

Um binário, um alvo, zero gordura: só o núcleo do servidor.

⚡

UDP + TCP iguais

Mesmo fluxo Photon nos dois transportes. TCP via framing com prefixo de tamanho, mesmas operações e respostas.

🔒

Cripto de verdade

Diffie-Hellman Oakley-768 + AES-256-CBC com handshake de init-encryption negociado por peer.

🎯

Um alvo só

aarch64-unknown-linux-gnu. Sem enquetes de plataforma, sem #ifdef de Windows, 3DS ou WASM.

🗂️

SQL Lobbies

Filtros C0..C9 com LIKE/GLOB, AND/OR/NOT e cadeia de até 3 queries, igual ao original.

📦

Núcleo mínimo

Apps, lobbies, salas, peers, matchmaking. Sem webserver, plugins, FFI ou telemetria.

🧩

Core separado

Biblioteca de protocolo (Core/) como submódulo próprio, versionada à parte.

Quickstart

Do zero ao servidor ouvindo.

# 1. build (Ubuntu ARM64 ou cross)
cmake -B build --toolchain cmake/toolchain-aarch64-ubuntu-unknown.cmake \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build

# 2. configure (troque pelos IPs da sua máquina)
cp config.example.yml config.yml

# 3. rode
./build/corerealtime config.yml

CoreRealtime ready — listening on 6 server(s)

  1. Libere no firewall as UDP 5055–5058 e 27000–27002 (+ TCP 4530/4531/4533 se usar proxies).
  2. Aponte ns.exitgames.com e ns.photonengine.io para o IP do servidor.
  3. Abra o jogo — ele conecta achando que é a nuvem oficial.
